02 / THE WORKSHOP SPLIT

Maintenance and making.
One roof, two satellites.

RT:WORKSHOP should not become a drawer of unrelated utilities. Its two satellites separate device care from user and developer tools.

SYS01
SATELLITE A / DEVICE CARE

SYSTEMS

Telemetry and diagnostics with clear provenance, plus maintenance operations with explicit safety boundaries.

  • Device and OS inventory
  • CPU, temperature, memory and storage telemetry
  • Logs and redacted support bundles
  • Backup, restore, safe cleanup and repair
  • Destructive actions behind confirmation
TL02
SATELLITE B / USER UTILITIES

TOOLS

Utilities that help users and developers work on the device without requiring a full desktop session.

  • RT:Shell as a PTY utility
  • Python executor with timeouts and bounded output
  • Calculator, clock, calendar, notes and file utilities
  • QWASAR Inspector and Switchboard when connected
  • Jobs run outside render and input callbacks
03 / DELIVERY GATES

Build in layers.
Prove each one.

A release is a chain of evidence. Feature presence, CI success and hardware certification are different claims.

M0
FOUNDATIONS

Device detector, semantic actions, schemas and baseline documentation.

UNIT TESTS / DETECTED METADATA
M1
STABILITY

Services, lifecycle, jobs, shell and executor boundaries.

TIMEOUT / ERROR / CANCEL TESTS
M2
NEXUS

Navigation, controller focus and global operation overlay.

CONTROLLER-DRIVEN FLOW
M3
UPLINK + WORKSHOP

Network services, telemetry and the SYSTEMS / TOOLS satellites.

REAL SERVICE STATES / RECOVERY
M4
SETTINGS

Identity, profiles, privacy, device cockpit and migrations.

PERSISTENCE / REVOCATION
M5
CONVERGENCE

Shared UI and service contracts with explicit capability ownership.

NO UNOWNED ROUTES
M6
RELEASE

Package, upgrade, rollback and target device qualification.

PHYSICAL H700 MATRIX
!

Safety invariant — keep the native firmware boot, launcher and recovery path available. Do not replace bootloader partitions or silently change active controller mappings.
